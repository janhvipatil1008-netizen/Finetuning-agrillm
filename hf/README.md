# agri-llm-qwen2.5-7b-lora

> **⚠️ Research / portfolio model. NOT for real pesticide advice.**
> Its answers can be wrong in ways that harm crops, people and livestock.
> Always follow the product label, which is legally binding in India, and
> consult a local agriculture officer or a qualified agronomist.

## What it does

The model takes a farmer's question about a pest or disease and returns one
structured JSON advisory. The advisory gives likely causes, non-chemical
measures first, then chemical options with dose, basis, pre-harvest interval
(PHI) and cautions. It also says whether to escalate to an expert.

- **Scope.** Eight crops in Maharashtra, India: cotton, soybean, tur, gram,
  onion, tomato, grape and pomegranate.
- **Grounding.** The chemical facts it was trained on come from CIB&RC
  (Central Insecticides Board & Registration Committee) "Major Uses of
  Pesticides" label data: registered crop × pest pairs, product dose and PHI.

## Training

**Adapter.** LoRA on the 4-bit base model, trained with Unsloth + TRL SFT
(per the adapter's saved metadata).

| setting | value |
|---|---|
| base model | `unsloth/Qwen2.5-7B-Instruct-bnb-4bit` |
| LoRA r / alpha / dropout | 32 / 64 / 0 |
| target modules | `q_proj`, `k_proj`, `v_proj`, `o_proj`, `gate_proj`, `up_proj`, `down_proj` |
| epochs | 1 (from session record) |
| steps | 281 (from session record) |
| learning rate | 2e-4, cosine schedule, 20 warmup steps (from session record) |
| batch size | 2 per device × 8 gradient accumulation = 16 effective (from session record) |
| optimizer / precision / seed | adamw_8bit, weight decay 0.01 / fp16 / 42 (from session record) |
| max sequence length | 2048 (from session record) |
| GPU | Kaggle T4 (from session record) |
| training / held-out test examples | 4,493 / 1,136 |

The training cell ran on Kaggle and was never committed. The session-record
values have not been verified against a saved `trainer_state.json`; see
`reports/training_config.md` in the GitHub repository.

**The training data is synthetic:**

- **Inputs** are farmer queries, mostly from Kisan Call Centre (KCC) logs.
  Grape queries were constructed.
- **Answers** were generated by Claude (`claude-sonnet-4-6`) from those
  queries plus the matching CIB&RC label rows.
- **Filtering.** An answer was kept only if a deterministic verifier,
  checking it against the CIB&RC label data, gave it a perfect score.

### With the deterministic guard (R4)

The GitHub repository includes a post-generation guard (`src/guard.py`). It:
- removes chemical options that aren't registered for the crop and pest;
- removes options whose dose is outside the label range by more than 8%;
- forces escalation when the pre-harvest interval is unknown.

Counts are options / items.

| R4 | before guard | after guard |
|---|---:|---:|
| mean (498 items) | 0.5840 | 0.6597 |
| G2 (schema-valid) % | 91.0 | 100.0 |
| overdoses (WRONG_HIGH, RANGE_TOP) | 12 / 10 | 1 / 1 |
| per-hectare dose labelled per acre | 10 / 5 | 0 / 0 |
| unregistered chemicals (G5) | 3 / 1 | 1 / 1 |
| unknown-PHI options not escalated | 87 / 45 | 0 / 0 |
| false positives (removed options the verifier grades correct) | — | 0 (of 2 unregistered + 32 dose removals) |

The one overdose left after guarding (item B1_17) is a verifier rounding
defect; the dose itself matches the label.

**The guard reads the same label data as the scorer**, so its score gain
shows consistency between the two, not independent proof that the answers
are right.

## Known failure modes

- **Dose slips without the guard.** Before guarding, R4 wrote 12
  overdosed options and 10 per-hectare figures labelled as per acre on the
  benchmark.
- **Missed escalation on unknown PHI without the guard.** In 45 R4 answers
  (87 options), a product with an unknown pre-harvest interval was
  recommended without escalating to an expert.
- **Things the guard can't validate.**
  - Answers that fail the schema for any other reason pass through
    unchanged.
  - Queries where no crop can be identified are only escalated, not
    checked.
  - When no pest is identified, registration is checked at crop level
    only.
- **Base-prompt format issues.** Prompted with the schema alone, the base
  model wrapped 132 of 500 answers in `{"Advisory": …}`. This adapter
  wrapped none.
- **Narrow scope.** Eight crops only, all in Maharashtra.
- **Latin-script queries only (English and romanized Hindi); no
  Devanagari.**
- **No independent review.** Every score comes from the project's own
  verifier. No agronomist or expert has reviewed the answers.
- **Free text is not graded.** The verifier grades chemicals, doses, PHI and
  escalation (plus the top cause's name, and whether any non-chemical advice
  is given), not free text.
  - Example: benchmark item B4b_7 is a grape query, but its answer names
    "pomegranate" in its evidence. It still scores 1.000 once the guard
    escalates it.
- **A ground-truth basis error the scorer inherits.** The label database
  records **12 of its 38 seed-treatment rows** as per hectare, where the
  label's bare number means per kg of seed; 7 more are unclear. The scorer,
  the guard and the training data then all accept a per-acre dose for them.
  - **Reach:** it touches **7 benchmark items** and **52 of 4,493 training
    examples** (plus 11 of 1,136 test examples).
  - **Effect on the results:** excluding the 7 items moves no arm's mean
    by more than **+0.0069**, and no comparison's confidence interval
    changes sign. See `reports/phase14_clean_eval.md` §10 in the GitHub
    repository.
- **Loss over the whole sequence.** Training computed loss over system
  prompt + query + answer, not the answer only (from session record). The
  prompt is a median
  72.5% of each training sequence. A future run should use answer-only
  (completion-only) loss.
- **One training run.** There was no hyperparameter sweep and no repeat
  with other seeds.

## How to use

The R4 numbers above used a CIB&RC fact sheet in the user message, built by
`src/retrieval.py` in the GitHub repository. A bare query, as below,
corresponds to R3.

`tools/generate.py` in the repository is the exact script used for
evaluation. It uses Unsloth.

```python
from huggingface_hub import hf_hub_download
from peft import PeftModel
from transformers import AutoModelForCausalLM, AutoTokenizer

BASE = "unsloth/Qwen2.5-7B-Instruct-bnb-4bit"   # 4-bit: needs bitsandbytes and a CUDA GPU
ADAPTER = "Janhvi1008/agri-llm-qwen2.5-7b-lora"

tok = AutoTokenizer.from_pretrained(BASE)
model = AutoModelForCausalLM.from_pretrained(BASE, device_map="auto")
model = PeftModel.from_pretrained(model, ADAPTER)

# The frozen system prompt the adapter was trained with.
system = open(hf_hub_download(ADAPTER, "system_prompt.txt"), encoding="utf-8").read()

messages = [{"role": "system", "content": system},
            {"role": "user", "content": "Whitefly attack on my cotton, what should I spray?"}]
text = tok.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
inputs = tok(text, return_tensors="pt", add_special_tokens=False).to(model.device)

out = model.generate(**inputs, max_new_tokens=3072, do_sample=False, num_beams=1,
                     repetition_penalty=1.05)   # greedy, as evaluated
print(tok.decode(out[0, inputs["input_ids"].shape[1]:], skip_special_tokens=True))
```
