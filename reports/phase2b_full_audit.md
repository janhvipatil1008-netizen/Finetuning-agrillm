### 0.1 Method, in three lines
1. `missing_raw` / `extra_raw` — the Phase 2 character-multiset measure (`Counter(page text) - Counter(all lattice cells)` and the reverse), reproduced with **no** footer discount baked into the reference — the footer is classified by geometry instead (see 0.2).
2. Every text-layer word not found as a cell token is checked against the page's remaining `missing_raw` character budget. If its own characters aren't actually missing, it's an attribution artifact (camelot's cell-internal newlines, pdfplumber fusing overlapping glyph runs into a pseudo-word) and is dropped before classification — not a loss.
3. Everything left is placed in a zone relative to the union of camelot's ruled-table bboxes on that page — `inside` / `above` / `below` / `beside` — which is what decides benign vs. `REAL` (§2).

## 3. Regression tests — `tests/test_phi_parse.py`

No PHI-cell parser existed yet anywhere in the repo (Phase 3 has not started; `src/schema.py` is frozen and defines only the *shape* of `phi_days`, not how a raw cell becomes one). Added a single narrowly-scoped utility, `src/parse_phi.py` (`parse_phi(raw) -> Optional[int]`), and pinned it with two tests — this is groundwork Phase 3 will call, not Phase 3 itself: no camelot, no table iteration, no write to `data/final/`.

The bug both tests exist to catch is the same shape in both directions: Python's `0 or None` idiom silently turns a real zero into a missing value, and a naive "blank means safe" parser turns a missing value into a false zero. `src/schema.py` (frozen, Act 2) already depends on the distinction: `Advisory._invariants` requires `escalate_to_expert=True` exactly when `phi_days is None` — collapse the two and that guardrail fires on the wrong rows, or never fires at all.

| test | asserts | source |
|---|---|---|
| `test_polyoxin_d_zero_phi_parses_to_int_zero` | `parse_phi("0") == 0` and `is not None` | `fungicides_20260331.pdf` p23, Polyoxin D Zinc Salt 5% SC, Grape / Powdery Mildew — PHI cell is a bare `'0'` (verified verbatim below) |
| `test_placeholder_tokens_parse_to_none_not_zero` | `parse_phi("-") is None` and `parse_phi("N/A") is None` | placeholder tokens meaning "the label prints no number" |

Verbatim lattice cells, `fungicides_20260331.pdf` p23 (`Polyoxin D Zinc Salt 5% SC` sub-table, last row):

```text
Grape ‖ Powdery ↵Mildew ‖ 30 gm ‖ 600 gm ‖ 500 - 1000 ‖ 0
```

Both tests pass against the implementation added in this phase (`pytest tests/test_phi_parse.py -q` → `2 passed`), and both were confirmed to fail against the two classic regressions before being accepted: a `parsed or None` wrapper turns `parse_phi("0")` into `None` (fails test 1); a "blank/dash means safe" parser that maps placeholder tokens to `0` (fails test 2). Full test suite: `pytest tests/ -q` → `16 passed` (14 pre-existing + these 2).

Headings in these files are the same 11pt Times as body text, and not reliably inside or outside the ruled box (`Combination Product` and `PUBLIC HEALTH USE` are ruled-box cells; `Approved Uses of Registered Insecticides` is not). ## 5. Known limitations of this audit

- **Character-level, not semantic.** Two cells whose concatenated characters match the text layer are indistinguishable here even if camelot assigned them to the wrong row/column. This audit answers "was text dropped", not "was text placed correctly" — column-position stability was already covered in Phase 2 and is not re-litigated here.
- **`above`-zone REAL threshold is a heuristic** (>12 words or >1 numeric token defeats the "it's just a heading" default). It found zero false negatives on manual spot-check of the flagged pages, but it is a threshold, not a proof.
- **Section anchors are a fixed vocabulary (`SECTION_HEADINGS` in `tools/phase2b_audit.py`).** A heading phrased differently from every one seen in these 4 files would not be recognised. All 231 pages were swept and every page received a non-`unclassified` section (see the cached JSON's `per_page`), so there is no evidence of a missed heading in-scope — but the vocabulary was built by hand against exactly these 4 files, not derived independently.
